# 模型训练与实验准备说明

## 1. 结论

完成整个实验不需要训练大模型本身。当前系统使用大模型 API 验证真实 Agent 行为，API 模型只作为被保护或被攻击的外部大模型，不做微调。

从严谨角度看，建议训练的是 P3 敏捷感知模块中的轻量窗口级风险分类器。它对应实施计划中的 DistilBERT/TinyBERT/MiniLM 分类器，用来证明系统不仅依赖规则和关键词，还具备可学习的前置检测能力。

因此训练需求分成三类：

| 模块 | 是否需要训练 | 说明 |
| --- | --- | --- |
| 大模型 API | 不训练 | 使用 `DSS_LLM_API_KEY`、`DSS_LLM_BASE_URL`、`DSS_LLM_MODEL` 调用真实模型。 |
| P3 轻量感知分类器 | 建议训练 | 训练 DistilBERT 窗口级二分类器，替代当前 feature fallback。 |
| P4 双环验证专家 | 不训练 | 当前是反射审计、语义一致性、逻辑对齐、泄露专家；后续在线版应接 API 结构化审计，不做微调。 |
| P5 动态仲裁 | 不训练 | 属于规则/阈值策略；可在 valid 集上校准阈值。 |
| P6/P7 Agent | 不训练 | 做端到端 API 实验和对比实验。 |

一句话：如果只是把在线实验跑完，优先做大模型 API 测试；如果要让论文中的“轻量分类器”更扎实，需要训练 P3 的 DistilBERT 风险分类器。

## 2. 当前代码状态

当前 `src/dss_guard/perception/classifier.py` 支持传入本地 DistilBERT 路径，默认是：

```text
E:\distilbert-base-multilingual-cased
```

也可以通过环境变量覆盖：

```text
DSS_DISTILBERT_MODEL_PATH=E:\distilbert-base-multilingual-cased
```

但当前实现只检查 `torch` 和 `transformers` 是否存在，并没有真正加载微调后的 `AutoModelForSequenceClassification`。即使本地 DistilBERT 路径存在，当前后端仍然是特征兜底：

```text
feature_fallback
distilbert_configured_feature_fallback
```

所以如果要完成训练版实验，需要新增两部分能力：

1. 训练脚本，例如 `experiments/train_perception_classifier.py`。
2. 推理加载逻辑，让 `build_classifier()` 能加载训练后的 sequence-classification checkpoint。

## 3. 需要训练什么模型

推荐训练一个模型：

```text
distilbert-base-multilingual-cased 窗口级二分类器
```

基础模型路径：

```text
E:\distilbert-base-multilingual-cased
```

训练输出路径建议：

```text
outputs/models/perception_distilbert_v1
```

任务定义：

1. 输入：外部检索内容切片后的窗口文本。
2. 输出：该窗口是否包含间接提示注入风险。
3. 标签：
   - `0`：clean/安全窗口。
   - `1`：attack/风险窗口。

可选增强任务：

1. 多分类攻击类型：`plain`、`html_hidden`、`adversarial_suffix`、`fake_system`、`leakage`、`logic_trap`、`mixed`。
2. span 辅助任务：预测窗口是否覆盖 `malicious_spans`。

最小可交付版本只需要二分类。不要一开始做多任务，样本量还偏小，容易把实现复杂度抬高。

## 4. 训练数据如何准备

现有数据文件：

```text
data/processed/train.jsonl
data/processed/valid.jsonl
data/processed/test.jsonl
```

当前划分：

| split | 数量 |
| --- | ---: |
| train | 210 |
| valid | 45 |
| test | 45 |

每条样本包含：

```text
case_id
user_query
external_content
attack_type
label
malicious_spans
work_focus
tool_risk
```

训练时不要直接把整篇 `external_content` 当作唯一输入，应该复用 P3 的滑动窗口切片逻辑：

```text
window_size=384
overlap_ratio=0.5
max_windows=64
```

窗口标签建议：

1. clean 样本的所有窗口标为 `0`。
2. attack 样本中，与任一 `malicious_spans` 有重叠的窗口标为 `1`。
3. attack 样本中没有覆盖恶意 span 的普通正文窗口标为 `0`。
4. 如果某条 attack 样本缺少 `malicious_spans`，不要用于窗口级训练，或只用于 case-level 弱监督。

这样训练出来的模型才会学习“外部内容中哪一段危险”，而不是只记住整篇文章的主题。

## 5. 需要准备什么

### 5.1 本地模型

确认本地模型目录存在：

```powershell
Test-Path E:\distilbert-base-multilingual-cased
```

目录中通常应包含：

```text
config.json
tokenizer.json 或 vocab.txt
model.safetensors 或 pytorch_model.bin
```

### 5.2 Python 依赖

当前 `pyproject.toml` 尚未包含训练所需依赖。训练前建议补充：

```text
torch
transformers
scikit-learn
numpy
tqdm
```

如果使用 Hugging Face Trainer，还需要：

```text
accelerate
```

如果只写自定义 PyTorch 训练循环，可以不依赖 `datasets`。

### 5.3 硬件

最低要求：

1. CPU 可训练，但会慢。
2. 有 NVIDIA GPU 更好，6GB 显存以上较稳。
3. 小数据集训练 3 到 5 个 epoch 即可，不建议长时间训练。

### 5.4 环境变量

训练分类器：

```text
DSS_DISTILBERT_MODEL_PATH=E:\distilbert-base-multilingual-cased
```

在线大模型实验：

```text
DSS_LLM_API_KEY=...
DSS_LLM_BASE_URL=...
DSS_LLM_MODEL=qwen-plus
DSS_NUM_TRIALS=5
DSS_DELAY_BETWEEN_TRIALS=1
```

不要把 `.env` 提交到 Git。

## 6. 推荐训练流程

### 6.1 构造窗口级训练集

新增脚本目标：

```text
experiments/build_perception_windows.py
```

输入：

```text
data/processed/train.jsonl
data/processed/valid.jsonl
data/processed/test.jsonl
```

输出：

```text
outputs/training/perception_windows_train.jsonl
outputs/training/perception_windows_valid.jsonl
outputs/training/perception_windows_test.jsonl
```

每行格式建议：

```json
{
  "case_id": "attack_plain_0035",
  "window_id": "attack_plain_0035:w0000",
  "text": "窗口文本",
  "label": 1,
  "attack_type": "plain",
  "start": 0,
  "end": 384,
  "overlaps_malicious_span": true
}
```

### 6.2 训练 DistilBERT 二分类器

新增脚本目标：

```text
experiments/train_perception_classifier.py
```

推荐参数：

```powershell
uv run python -m experiments.train_perception_classifier `
  --model-path E:\distilbert-base-multilingual-cased `
  --train-file outputs\training\perception_windows_train.jsonl `
  --valid-file outputs\training\perception_windows_valid.jsonl `
  --output-dir outputs\models\perception_distilbert_v1 `
  --epochs 5 `
  --batch-size 8 `
  --learning-rate 2e-5 `
  --max-length 384 `
  --seed 2026
```

训练时记录：

1. train loss。
2. valid precision。
3. valid recall。
4. valid F1。
5. valid AUROC。
6. 最佳 checkpoint 的 epoch。

### 6.3 阈值校准

不要直接固定 `0.5`。建议在 valid 集上寻找阈值：

```text
threshold ∈ {0.20, 0.25, 0.30, ..., 0.80}
```

选择原则：

1. Recall 优先，不低于 0.90。
2. Precision 不低于 0.75。
3. FAR 尽量低。
4. 平均延迟仍明显低于全量 LLM 审计。

校准结果写入：

```text
outputs/models/perception_distilbert_v1/calibration.json
```

示例：

```json
{
  "threshold": 0.35,
  "valid_precision": 0.92,
  "valid_recall": 0.96,
  "valid_f1": 0.94,
  "valid_auroc": 0.98
}
```

### 6.4 接入 P3 推理

训练后需要让 `src/dss_guard/perception/classifier.py` 支持：

```text
AutoTokenizer.from_pretrained(checkpoint_path)
AutoModelForSequenceClassification.from_pretrained(checkpoint_path)
```

模型推理输出：

```text
classifier_score = softmax(logits)[attack_label]
backend = distilbert_sequence_classifier
```

如果 checkpoint 不存在或加载失败，再回退到当前 feature fallback。

## 7. 训练后如何验证

### 7.1 P3/P7.2 感知层评估

训练并接入后运行：

```powershell
uv run python -m experiments.run_perception_eval `
  --input data\processed\test.jsonl `
  --method all `
  --classifier-model-path outputs\models\perception_distilbert_v1 `
  --metrics-output outputs\tables\perception_metrics_trained.csv `
  --log-output outputs\logs\perception_eval_trained.jsonl `
  --require-stage-pass
```

必须比较：

1. feature fallback 结果。
2. trained DistilBERT single_classifier。
3. trained DistilBERT window_classifier。
4. fusion 结果。

### 7.2 P7.4 在线端到端评估

训练模型接入后，再运行在线端到端防御对比：

```powershell
uv run python -m experiments.run_end_to_end_eval `
  --input data\processed\test.jsonl `
  --strategy all `
  --use-api `
  --stage p7_api_end_to_end_eval `
  --metrics-output outputs\tables\end_to_end_metrics_api_trained.csv `
  --log-output outputs\logs\end_to_end_eval_api_trained.jsonl
```

注意：当前 `GuardedAgent` 内部使用 `PerceptionConfig(prefer_model=False)`，如果要让端到端也使用训练后的 DistilBERT，需要额外改造配置传递，否则训练模型只会影响 P7.2 感知评估，不会进入 P6/P7.4 端到端流程。

## 8. 训练是否影响在线 API 实验

训练 DistilBERT 不会替代大模型 API 实验。

二者作用不同：

1. 大模型 API 实验验证真实 LLM Agent 是否会被攻击、是否能被防御。
2. DistilBERT 训练验证前置轻量感知模块是否具备学习能力和低延迟检测能力。

所以完整可靠性补充建议分成两条线：

1. 在线 API 线：继续完成 4.3、P7.3 在线反射审计、P7.5 在线消融、P7.6 真实延迟。
2. 训练线：训练 P3 DistilBERT 分类器，并重新跑 P7.2 和端到端训练版对比。

## 9. 不建议训练的内容

### 9.1 不建议微调大模型

原因：

1. 当前研究对象是防御框架，不是训练一个更安全的大模型。
2. 微调大模型成本高，且会改变被攻击模型本身，不利于比较防御层效果。
3. 当前目标是证明外部检索源间接提示注入下，防御层能保护通用 API 模型。

### 9.2 不建议训练 P4 专家

P4 专家现在承担的是结构化审计、语义一致性、逻辑对齐和泄露检查。更合适的方向是：

1. 接入真实 LLM 结构化审计。
2. 加强 JSON 解析和失败兜底。
3. 用人工标注或规则标签评估审计结果。

不需要先训练一个新的 P4 模型。

### 9.3 不建议训练 P5 仲裁器

P5 当前是动态阈值和审计深度策略。现阶段建议做 valid 集阈值校准，而不是训练黑盒仲裁器。

## 10. 最小训练验收标准

如果决定训练 P3 分类器，至少满足：

1. 训练脚本可复现，固定随机种子。
2. 训练数据只使用 train split。
3. 阈值只在 valid split 上选择。
4. 最终指标只在 test split 上报告。
5. 训练后的 `single_classifier` 和 `window_classifier` 使用真实 checkpoint，而不是 `feature_fallback`。
6. 输出中记录 `classifier_backend=distilbert_sequence_classifier`。
7. P7.2 trained 版本至少达到：
   - Recall >= 0.90
   - Precision >= 0.75
   - 平均延迟 < 50 ms
8. 报告 trained 与 fallback 的差异，不只报告最好结果。

## 11. 推荐执行顺序

第一步，继续完成在线 API 实验：

1. P7.4 端到端在线防御对比。
2. P7.3 在线结构化反射审计。
3. P7.5 在线消融。
4. P7.6 真实 API 延迟。

第二步，再补训练线：

1. 新增窗口级数据构造脚本。
2. 新增 DistilBERT 训练脚本。
3. 新增训练 checkpoint 加载逻辑。
4. 重新跑 P7.2 trained 对比。
5. 重新跑端到端 trained 版本。

第三步，写最终实验结论：

1. 离线规则/特征原型结果。
2. 真实大模型 API 在线结果。
3. 训练后轻量分类器结果。
4. 三者分别说明，不混在同一张表里。

## 12. 最终表述口径

如果不训练 P3 分类器，可以这样写：

> 本实验中的敏捷感知模块采用规则、统计异常特征和轻量特征分类器实现，当前未对 DistilBERT 进行任务微调；其作用是验证低延迟前置检测链路。真实大模型安全性通过在线 API 攻击复现与端到端防御实验验证。

如果训练了 P3 分类器，可以这样写：

> 本实验基于 `distilbert-base-multilingual-cased` 微调了窗口级间接提示注入风险分类器，并与规则、统计异常特征融合。训练仅使用 train split，阈值在 valid split 上校准，最终结果在 test split 和真实大模型 API 端到端场景中报告。
