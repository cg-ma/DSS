# 基于意图流转一致性的间接提示注入动态防御实现规划

## 1. 规划目标

本规划依据 `docs/开题报告.txt` 中的研究目标、技术路线和专家修改意见，将论文方案落地为可执行的工程实现、实验设计和阶段性交付计划。

本项目建议将实际场景收敛为：

> 联网 RAG / 网页摘要型 LLM Agent 在读取外部网页、文档或搜索结果时遭遇间接提示注入攻击，防御系统在“外部内容进入上下文”和“Agent 调用工具/生成最终回答”两个关键位置进行动态守卫。

这样可以回应开题记录中的“题目比较宽泛，没有和实际场景关联”问题，也便于围绕已有 `experiments/attacker_server.py`、`experiments/run_attack_reproduction.py` 的攻击复现脚本继续扩展。

### 1.1 工作重点对齐

摘要中的工作重点可以归纳为“三个问题、三个模块、三类实验”。后续实现和论文叙述都应围绕这三条主线展开，数据集构建、攻击复现和工程整理只作为支撑工作。

| 摘要中的问题 | 对应方法 | 工程落点 | 核心验证实验 |
| --- | --- | --- | --- |
| 前置检测模型推理延迟高，实时交互效果不理想 | 重叠滑动窗口 + 轻量化类 BERT 分类器 + 困惑度过滤器 | 敏捷感知模块 | 显式指令载荷与对抗性乱码检测、长文本延迟实验 |
| 单一模态防御存在盲区，对数据泄露与逻辑陷阱泛化弱 | 基于混合专家的双环验证，结合反射式智能体、语义一致性和逻辑对齐检测 | 双环意图验证模块 | 数据泄露诱导、隐蔽逻辑陷阱、工具调用偏离实验 |
| 静态阈值难以兼顾防御强度与可用性 | 基于风险标签的动态风险仲裁，动态调整通过阈值和审计深度 | 动态风险仲裁模块 | 固定阈值对比、不同风险等级下的审计深度与延迟实验 |

## 2. 研究边界与创新点重构

### 2.1 建议聚焦的研究问题

摘要已经明确了本文的核心工作重点。为避免“研究内容太多，没有突出创新点”，实现阶段不再平均铺开所有安全机制，而是围绕以下三项工作组织：

1. 敏捷感知模块：面向外部检索源中的显式指令载荷和对抗性乱码，重点解决前置检测延迟高的问题。
2. 基于混合专家的双环验证方法：通过反射式智能体进行意图修正，并融合语义一致性度量与逻辑对齐检测，重点补足数据泄露和隐蔽逻辑陷阱的检测盲区。
3. 动态风险仲裁算法：依据感知层输出的风险标签，自适应调整通过阈值和审计深度，重点解决安全性与可用性的动态平衡问题。

数据集构建不作为独立研究创新点，而作为实验基准与训练评估支撑，放入实验部分。

### 2.2 最小可发表系统定义

系统最小闭环包括：

1. 一个可复现实验场景：用户请求总结网页，Agent 检索到含有恶意隐藏指令的网页。
2. 一个攻击基准：覆盖外部检索源中的显式指令载荷、HTML 隐藏注入、伪造系统消息、对抗性乱码、逻辑陷阱、数据泄露诱导。
3. 一个防御架构：感知层先快速打分，疑似风险进入双环验证，最终由动态仲裁层决定放行、清洗、深度审计或阻断。
4. 一组对比实验：无防御、关键词规则、单一分类器、单一 LLM 审计、本文动态防御。
5. 一组指标：攻击成功率、拦截率、误报率、首字延迟、端到端延迟、审计调用次数、成本。

## 3. 总体系统架构

系统采用“从感知输入到动作执行”的全链路意图守卫结构：

1. 输入与场景层：负责网页抓取、HTML 清洗、RAG 上下文构造、攻击样本注入。
2. 敏捷感知层：负责长文本切片、轻量分类、困惑度统计、规则弱信号检测，输出初步风险标签。
3. 双环意图验证层：负责反射式意图修正、语义一致性检查、逻辑对齐检测和数据泄露风险识别。
4. 动态风险仲裁与执行层：负责根据风险标签动态调整通过阈值和审计深度，并输出允许、清洗、深度审计或阻断决策。

推荐处理流程：

```text
用户问题
  -> 检索/抓取外部内容
  -> 内容清洗与结构化
  -> 敏捷感知层输出 RiskSignal
  -> 动态仲裁判断审查深度
  -> 低风险：直接进入 Agent
  -> 中风险：意图一致性检查 + 内容改写
  -> 高风险：反射式意图修正 + 逻辑对齐检测 + 工具调用前审计
  -> 输出 DefenseVerdict
  -> Agent 生成回答或阻断提示
  -> 记录实验日志
```

## 5. 核心数据结构设计

建议先定义统一的数据结构，避免后续模块接口混乱。

```python
from dataclasses import dataclass, field
from typing import Any, Literal

RiskLevel = Literal["low", "medium", "high", "critical"]
VerdictAction = Literal["allow", "sanitize", "audit", "block"]

@dataclass
class ExternalContent:
    source_id: str
    source_type: str
    raw_text: str
    clean_text: str
    metadata: dict[str, Any] = field(default_factory=dict)

@dataclass
class TextWindow:
    window_id: str
    start: int
    end: int
    text: str

@dataclass
class RiskSignal:
    risk_level: RiskLevel
    score: float
    matched_spans: list[tuple[int, int]]
    reasons: list[str]
    features: dict[str, float]

@dataclass
class IntentSnapshot:
    user_goal: str
    allowed_actions: list[str]
    forbidden_actions: list[str]
    sensitive_slots: list[str]

@dataclass
class ActionRequest:
    tool_name: str
    tool_args: dict[str, Any]
    rationale: str
    untrusted_sources: list[str]

@dataclass
class DefenseVerdict:
    action: VerdictAction
    risk_score: float
    reasons: list[str]
    sanitized_text: str | None = None
```

## 6. 模块实现规划

### 6.1 输入与攻击复现场景

目标：

1. 复现无防御 Agent 被外部网页中的隐藏指令劫持。
2. 为后续防御模块提供稳定、可重复、可量化的实验入口。

实现内容：

1. 恶意网页服务：保留本地 HTTP 服务，扩展多种 payload 路径。
2. 网页抓取器：封装 `requests` 与 `BeautifulSoup`，保留原始 HTML、可见文本、隐藏文本。
3. RAG 上下文构造器：统一构造 `用户问题 + 外部内容 + 系统提示`。
4. 实验日志：记录 prompt、模型输出、攻击是否成功、耗时、模型名称。

攻击样本类别：

这里的“显式指令载荷”不是用户直接输入给模型的直接提示注入，而是被放置在网页、文档、邮件或搜索结果等外部数据源中的间接提示注入样本。阶段一保留少量外部显式载荷，是为了建立最基础的攻击复现和检测下限；论文主线仍然是 Agent 读取不可信外部内容后被劫持的间接提示注入。

| 类别 | 样例形式 | 对应工作重点 | 目的 |
| --- | --- | --- | --- |
| 外部显式指令载荷 | 网页正文或文档段落中出现“忽略之前所有指令” | 敏捷感知 | 验证间接注入的基础复现能力 |
| HTML/CSS/注释隐藏指令 | `display:none`、白色字体、HTML 注释、PDF 隐藏文本 | 敏捷感知 | 模拟真实检索源中的隐蔽载荷 |
| 对抗性乱码与扰动后缀 | 随机后缀、分隔符扰动、拼写扰动、多语混杂 | 敏捷感知 | 验证 PPL 过滤和轻量分类器的鲁棒性 |
| 伪造系统消息 | `[SYSTEM MESSAGE]`、`<|system|>`、伪造工具返回格式 | 双环验证 | 验证边界混淆与意图修正能力 |
| 数据泄露诱导 | 要求输出 token、联系人、历史消息、私有配置 | 双环验证 | 验证数据泄露检测盲区的补足效果 |
| 隐蔽逻辑陷阱 | 正文中诱导调用无关工具、打开外链或执行非授权操作 | 双环验证 | 验证逻辑对齐检测能力 |
| 混合风险场景 | 隐藏指令 + 乱码扰动 + 工具调用诱导 | 动态仲裁 | 验证不同风险标签下的阈值和审计深度调节 |

交付物：

1. `experiments/run_attack_reproduction.py`
2. `data/benchmark/ipi_cases.jsonl`
3. `outputs/tables/attack_reproduction.csv`

验收标准：

1. 无防御 Agent 在至少 3 类攻击样本上出现可观测攻击成功。
2. Clean 样本能保持正常摘要行为。
3. 每次实验都能自动输出 ASR、平均延迟和样本级日志。

### 6.2 敏捷感知层

目标：

在外部内容进入 LLM 上下文之前，以低延迟方式识别检索源中的显式指令载荷、隐藏指令和对抗性乱码片段，解决长文本前置检测的实时性问题。该模块重点负责“快筛”和风险标签输出，不单独承担数据泄露与复杂逻辑陷阱的完整判断，后者交给双环验证模块处理。

子模块：

1. `segmenter.py`：重叠滑动窗口切片。
2. `rules.py`：针对外部显式指令、伪造系统边界和隐藏文本的高精度弱规则检测。
3. `ppl_filter.py`：困惑度或统计异常特征。
4. `classifier.py`：DistilBERT / TinyBERT / MiniLM 二分类器。
5. `risk_fusion.py`：多信号融合输出风险标签，为动态仲裁提供初始风险依据。

滑动窗口策略：

```text
输入文本长度 N
窗口长度 W：建议 256 或 384 tokens
重叠步长 S：建议 W / 2
对每个窗口独立计算风险分数
将窗口风险映射回原文 span
全文风险 = max(window_score) + span_density_adjustment
```

风险融合建议：

```text
risk_score =
  0.45 * classifier_score
  + 0.20 * ppl_anomaly_score
  + 0.20 * rule_score
  + 0.15 * hidden_text_score
```

风险等级：

| 等级 | 分数范围 | 后续动作 |
| --- | --- | --- |
| low | 0.00 - 0.35 | 直接放行，记录日志 |
| medium | 0.35 - 0.60 | 内容清洗 + 语义一致性检查 |
| high | 0.60 - 0.82 | 进入反射式审计与工具调用前审计 |
| critical | 0.82 - 1.00 | 默认阻断或仅返回安全摘要 |

训练数据：

1. 正样本：外部显式指令载荷、伪造系统消息、隐藏 HTML 文本、对抗性乱码、工具调用诱导。
2. 负样本：正常新闻、技术文档、论文摘要、产品介绍、网页评论。
3. 难负样本：包含“系统”“忽略”“指令”等词但语义正常的安全文章。

指标：

1. Precision、Recall、F1、AUROC。
2. 每 1k tokens 平均检测耗时。
3. 长文本下 p95 延迟。
4. 恶意 span 定位准确率，重点统计显式指令载荷、隐藏指令和对抗性乱码三类样本。

交付物：

1. `src/dss_guard/perception/segmenter.py`
2. `src/dss_guard/perception/rules.py`
3. `src/dss_guard/perception/classifier.py`
4. `src/dss_guard/perception/risk_fusion.py`
5. `experiments/run_perception_train.py`

验收标准：

1. 在混合测试集上 F1 达到可写入论文的有效提升。
2. 与全量 LLM 审计相比，平均前置检测延迟明显更低。
3. 能输出可解释的风险原因和风险片段。

### 6.3 基于混合专家的双环意图验证

目标：

将防御视角从“外部内容是否恶意”扩展到“Agent 的动作是否忠于用户原始意图”。该模块对应摘要中的“基于混合专家的双环验证方法”，重点弥补单一模态防御对数据泄露与隐蔽逻辑陷阱的检测盲区。

双环结构：

1. 内环：反射式意图修正。对疑似风险上下文进行用户原始意图重构，过滤外部检索源中的诱导性目标。
2. 外环：混合专家验证。由语义一致性专家、逻辑对齐专家、数据泄露风险专家协同判断候选动作或最终回答是否偏离用户意图。

实现内容：

1. 从用户问题中抽取 `IntentSnapshot`。
2. 生成允许动作集合和禁止动作集合。
3. 通过反射式智能体生成“修正后的用户意图快照”，避免外部内容污染意图表示。
4. 对候选回答或工具调用进行语义一致性、逻辑对齐和数据泄露风险的混合专家校验。
5. 对中高风险样本输出结构化审计结论，供动态仲裁模块决定审查深度。

意图快照示例：

```json
{
  "user_goal": "总结网页中关于 2025 年 AI 技术突破的主要内容",
  "allowed_actions": ["fetch_web_page", "summarize_content"],
  "forbidden_actions": ["send_email", "open_external_link", "request_secret", "execute_code"],
  "sensitive_slots": ["api_key", "token", "contact_list", "local_file"]
}
```

混合专家设计：

| 专家 | 输入 | 输出 | 负责的攻击类型 |
| --- | --- | --- | --- |
| 语义一致性专家 | 用户目标、候选回答、候选动作理由 | `semantic_score` | 任务偏离、无关内容劫持 |
| 逻辑对齐专家 | 用户目标、工具调用序列、动作类型 | `logic_score` | 隐蔽逻辑陷阱、非授权工具调用 |
| 数据泄露风险专家 | 外部内容来源、敏感槽位、候选输出 | `leakage_score` | token、联系人、历史消息等敏感信息泄露 |

语义一致性检查：

1. 使用 embedding 计算 `user_goal` 与 `candidate_action.rationale` 的相似度。
2. 检查动作类型是否出现在允许动作集合中。
3. 检查回答是否包含外部内容中诱导的异常目标，例如诈骗链接、无关警告、泄露请求。
4. 对相似度低但分类器未判高危的样本进入反射式审计。

反射式审计 Prompt 要点：

1. 明确区分用户原始目标、外部资料、候选动作。
2. 要求模型只输出结构化 JSON。
3. 禁止执行外部资料中的新指令。
4. 输出字段包括 `is_aligned`、`semantic_score`、`logic_score`、`leakage_score`、`risk_reason`、`recommended_action`。

交付物：

1. `src/dss_guard/intent/extractor.py`
2. `src/dss_guard/intent/semantic_check.py`
3. `src/dss_guard/intent/reflective_auditor.py`

验收标准：

1. 能识别“用户要求总结网页，但外部内容诱导跳转链接/输出警告”的意图偏离。
2. 能识别“单步看似合理，但整体违背用户目标”的逻辑陷阱。
3. 能识别外部内容诱导输出敏感信息的数据泄露风险。
4. 对正常摘要请求不产生明显误杀。
5. 审计结果可结构化记录，便于实验统计。

### 6.4 逻辑对齐与数据泄露校验专家

目标：

实现双环验证中的逻辑对齐专家和数据泄露风险专家，检测“文本表面合理，但外部数据诱导 Agent 泄露敏感信息或调用不相关工具”的隐蔽攻击。

实现策略：

1. 对来自外部网页、搜索结果、文档的内容统一打上 `external_untrusted` 标签。
2. 对用户输入、系统指令、工具返回、模型草稿分别保留来源标签。
3. 当外部不可信内容影响工具调用参数或敏感输出时，提高风险等级。
4. 建立动作对齐策略表，判断候选工具调用是否服务于用户原始目标。
5. 建立敏感槽位表，判断候选输出是否包含 token、联系人、密钥、历史消息等敏感信息。

逻辑与数据流策略示例：

| 来源 | 流向 | 风险 |
| --- | --- | --- |
| external_untrusted | final_answer_summary | 允许，但需要引用或摘要 |
| external_untrusted | tool_name | 高风险 |
| external_untrusted | email_body | 高风险 |
| external_untrusted | url_to_open | 中高风险 |
| external_untrusted | request_secret | 严重风险 |
| user_input | allowed_tool_args | 低风险 |

交付物：

1. `src/dss_guard/alignment/logic_expert.py`
2. `src/dss_guard/alignment/data_flow_check.py`
3. `src/dss_guard/alignment/policy.py`

验收标准：

1. 能记录候选工具调用参数的来源。
2. 当外部网页内容直接诱导工具调用时，能触发阻断或审计。
3. 当候选输出包含敏感槽位或敏感信息请求时，能触发数据泄露风险告警。
4. 能在实验中分别输出逻辑陷阱命中次数和数据泄露风险命中次数。

### 6.5 动态风险仲裁算法

目标：

根据感知层风险标签和双环验证结果动态调整防御强度，避免固定阈值带来的过防御或漏防。该模块对应摘要中的“依据感知层输出的风险标签，自适应调整防御仲裁层的通过阈值与审计深度”。

输入信号：

1. 感知层风险分数 `p_perception`。
2. 语义一致性分数 `s_semantic`。
3. 逻辑偏离分数 `p_logic`。
4. 数据泄露风险分数 `p_leakage`。
5. 工具危险等级 `tool_risk`。
6. 历史会话风险 `session_risk`。

建议仲裁公式：

```text
R_t = sigmoid(
  a * p_perception
  + b * (1 - s_semantic)
  + c * p_logic
  + d * p_leakage
  + e * tool_risk
  + f * session_risk
)
```

动态动作：

| 仲裁风险 | 审查深度 | 动作 |
| --- | --- | --- |
| L0 | 无额外审查 | allow |
| L1 | 清洗高危片段 | sanitize |
| L2 | 反射式审计一次，运行语义一致性专家 | audit |
| L3 | 反射式审计 + 逻辑对齐专家 + 数据泄露风险专家 + 工具前审计 | audit/block |
| L4 | 严重违规 | block |

伪代码：

```python
def arbitrate(risk_signal, semantic_check, logic_check, leakage_check, action_request):
    risk = fuse(
        risk_signal.score,
        1 - semantic_check.score,
        logic_check.deviation_score,
        leakage_check.risk_score,
        action_request.tool_risk,
    )

    if risk < 0.35:
        return DefenseVerdict(action="allow", risk_score=risk, reasons=[])
    if risk < 0.60:
        return DefenseVerdict(action="sanitize", risk_score=risk, reasons=["medium risk content"])
    if risk < 0.82:
        return DefenseVerdict(action="audit", risk_score=risk, reasons=["high risk alignment check"])
    return DefenseVerdict(action="block", risk_score=risk, reasons=["critical injection risk"])
```

交付物：

1. `src/dss_guard/arbitration/dynamic_policy.py`
2. `src/dss_guard/arbitration/verdict.py`
3. `tests/test_dynamic_policy.py`

验收标准：

1. 低风险样本保持较低延迟。
2. 高风险样本触发更深审计。
3. 动态策略相对固定阈值在 ASR/FAR/Latency 上有综合优势。

### 6.6 Guarded Agent 集成

目标：

将防御架构接入实际 Agent 流程，形成可运行的端到端原型。

关键拦截点：

1. 外部内容进入上下文前：内容风险感知与清洗。
2. LLM 生成工具调用前：动作意图对齐、逻辑偏离和数据泄露风险检查。
3. 最终回答输出前：检查是否包含注入诱导结果或敏感泄露。

推荐 Agent 流程：

```text
fetch_web_content(url)
  -> ExternalContent
  -> guard.scan_content()
  -> guard.sanitize_or_audit()
  -> LLM draft / tool plan
  -> guard.check_action()
  -> execute allowed action
  -> guard.check_final_answer()
  -> final response
```

交付物：

1. `src/dss_guard/agent/rag_agent.py`
2. `src/dss_guard/agent/guarded_agent.py`
3. `experiments/run_end_to_end_eval.py`

验收标准：

1. 无防御 Agent 可被攻击样本劫持。
2. Guarded Agent 能阻断或清洗多数攻击样本。
3. 正常网页摘要任务保持可用。

## 7. 实验设计

### 7.1 实验一：攻击复现与场景确认

目的：

证明实验场景中确实存在间接提示注入威胁，为防御实验提供基线。

对比对象：

1. 无防御 Agent。
2. 系统提示加强但无外部检测的 Agent。

指标：

1. ASR：攻击成功率。
2. Clean Success Rate：正常摘要成功率。
3. 平均响应延迟。

预期结论：

仅依靠系统提示无法稳定抵抗外部网页中的隐蔽注入。

### 7.2 实验二：敏捷感知层检测能力

目的：

验证重叠滑动窗口、轻量化类 BERT 分类器、PPL 过滤器对长文本外部检索源中显式指令载荷、隐藏指令和对抗性乱码的检测能力与时延优势。

对比对象：

1. 关键词规则。
2. 单一轻量分类器。
3. 轻量分类器 + 滑动窗口。
4. 轻量分类器 + 滑动窗口 + PPL/规则融合。

指标：

1. Precision、Recall、F1、AUROC。
2. 恶意片段定位准确率。
3. 平均检测耗时、p95 检测耗时、每 1k tokens 检测耗时。
4. 显式指令、隐藏指令、对抗性乱码三类样本的分项召回率。

预期结论：

融合方法相对单一方法能提升召回和长文本定位能力，同时延迟低于全量 LLM 审计，支撑“显著降低防御时延”的摘要结论。

### 7.3 实验三：双环验证补盲能力

目的：

验证基于混合专家的双环验证方法能否弥补单一模态感知层对数据泄露与隐蔽逻辑陷阱类攻击的检测盲区。

对比对象：

1. Perception Only：只使用敏捷感知层。
2. Semantic Only：只使用语义一致性度量。
3. Reflective Agent Only：只使用反射式审计。
4. MoE Dual-loop：反射式意图修正 + 语义一致性专家 + 逻辑对齐专家 + 数据泄露风险专家。

指标：

1. Logic Trap Recall：逻辑陷阱召回率。
2. Leakage Block Rate：数据泄露诱导阻断率。
3. Intent Alignment Accuracy：意图对齐判断准确率。
4. FAR：正常工具调用误报率。
5. Additional Audit Latency：双环验证带来的额外延迟。

预期结论：

双环验证能显著提升数据泄露和隐蔽逻辑陷阱类样本的检出率，并且比单纯依赖语义相似度更稳定。

### 7.4 实验四：端到端防御性能对比

目的：

验证完整系统相对基线方法在安全性、可用性和延迟上的综合优势。

对比对象：

1. No Defense。
2. Keyword Filter。
3. Perception Only。
4. LLM Auditor Only。
5. Static Threshold Defense。
6. Ours：Perception + MoE Dual-loop + Dynamic Arbitration。

指标：

1. ASR：攻击成功率，越低越好。
2. Defense Success Rate：攻击拦截率，越高越好。
3. FAR：误报率，越低越好。
4. TTFT：首字延迟。
5. E2E Latency：端到端延迟。
6. Audit Calls：每次请求平均 LLM 审计调用次数。

预期结论：

完整系统在较低 ASR 和可控 FAR 的前提下，比全量 LLM 审计具有更低延迟，并且比固定阈值策略更能兼顾安全性与可用性。

### 7.5 实验五：消融实验

目的：

说明摘要中三个核心模块的必要性，并突出创新点。

消融设置：

1. 去除滑动窗口，只检测截断前文。
2. 去除 PPL/规则特征，只保留分类器。
3. 去除反射式意图修正，只保留静态用户意图。
4. 去除逻辑对齐专家和数据泄露风险专家，只保留语义一致性专家。
5. 去除动态仲裁，改用固定阈值和固定审计深度。

指标：

1. ASR、FAR、F1。
2. 不同攻击类别下的防御成功率。
3. 延迟变化。

预期结论：

滑动窗口和 PPL 主要贡献低延迟感知能力；双环验证主要提升逻辑陷阱与数据泄露类攻击的检测能力；动态仲裁主要降低低风险场景的不必要审计开销。

### 7.6 实验六：动态仲裁延迟与可用性分析

目的：

验证动态风险仲裁在不同输入长度和风险等级下，能否通过调整通过阈值和审计深度实现安全性与可用性的平衡。

变量：

1. 输入长度：1k、4k、8k、16k tokens。
2. 风险等级：low、medium、high、critical。
3. 审查策略：固定阈值 + 固定审计深度、动态阈值 + 动态审计深度。

指标：

1. 平均延迟。
2. p95 延迟。
3. TTFT。
4. LLM 审计调用次数。
5. 不同风险等级下的平均审计深度。
6. 显存或内存占用。

预期结论：

动态仲裁在低风险场景下减少审计次数，在高风险场景下提高审查强度，实现安全性与可用性的平衡。

## 9. 指标定义

| 指标 | 定义 | 方向 |
| --- | --- | --- |
| ASR | 攻击样本中成功诱导 Agent 执行恶意目标的比例 | 越低越好 |
| DSR | 攻击样本中被正确阻断、清洗或审计拦截的比例 | 越高越好 |
| FAR | 正常样本中被错误阻断或错误审计为攻击的比例 | 越低越好 |
| Precision | 被判为攻击的样本中真实攻击比例 | 越高越好 |
| Recall | 真实攻击样本中被检出的比例 | 越高越好 |
| F1 | Precision 和 Recall 的调和平均 | 越高越好 |
| Logic Trap Recall | 隐蔽逻辑陷阱样本中被正确识别的比例 | 越高越好 |
| Leakage Block Rate | 数据泄露诱导样本中被正确阻断的比例 | 越高越好 |
| TTFT | 用户请求到首个输出 token 的时间 | 越低越好 |
| E2E Latency | 请求到最终回答完成的总耗时 | 越低越好 |
| Audit Calls | 单次请求触发 LLM 审计的平均次数 | 越低越好 |
| Audit Depth | 单次请求触发的平均审计深度 | 低风险越低，高风险越充分 |
| Cost | 单次请求模型调用成本或 token 数 | 越低越好 |
