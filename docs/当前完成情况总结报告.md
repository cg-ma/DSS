当前最主要的未完成工作已经从“工程实现和系统实验”转移到“论文与展示沉淀”：需要整理 P8 方法章节、实验章节、在线与离线结果口径、局限性分析和答辩演示材料。另一个可选增强项是训练 P3 DistilBERT 窗口级分类器，目前系统仍以规则、统计异常特征和 feature fallback 分类器为主。

## 4. 离线实验结果摘要

离线 P7.7 验收表 `outputs/tables/p7_acceptance.csv` 显示，6 张核心实验表和 6 张论文图表均存在且 `stage_pass=True`。核心表格包括攻击复现、感知性能、双环验证、端到端对比、消融实验和仲裁延迟；核心图表包括架构图、感知层检测性能对比图、双环补盲效果图、端到端 ASR/FAR 对比图、输入长度延迟曲线和动态仲裁审计深度曲线。

关键离线指标如下：

1. 攻击复现：正式测试集无防御离线基线总体 ASR 为 1.0，7 类攻击均可稳定成功。
2. 感知性能：fusion 方法 Precision 0.96、Recall 1.0、F1 0.979592、AUROC 1.0、span_accuracy 1.0，平均延迟约 0.292 ms。
3. 双环验证：MoE Dual-loop Precision/Recall/F1 均为 1.0，FAR 0.0，Logic Trap Recall 1.0，Leakage Block Rate 1.0。
4. 端到端防御：`ours` 将无防御 ASR 从 1.0 降至 0.0，DSR 1.0，Clean Success Rate 1.0，FAR 0.0。
5. 消融实验：去掉滑动窗口后 Long-tail Recall 从 1.0 降至 0.0；去掉规则/PPL 特征后 Perception Attack Recall 降至 0.306452；去掉动态仲裁后 FAR 从 0.0 升至 0.142857。
6. 仲裁延迟：动态仲裁在 low 风险场景将审计次数降为 0，在 high/critical 场景把审计深度提升到 4，体现低风险可用性和高风险安全性的动态平衡。

## 5. 在线 API 实验结果摘要

在线实验均独立输出为 `_api` 表格和日志，没有覆盖离线结果。

### 5.1 在线无防御攻击复现

`outputs/tables/attack_reproduction_api.csv` 显示，在线 P7.1 共运行 45 条正式测试样本、225 次真实 API 调用，错误数为 0。总体在线无防御 ASR 为 0.926316，Clean Success Rate 为 1.0，7 类攻击均出现成功样本。除 `mixed` 类型 ASR 为 0.3 外，其余 `plain`、`html_hidden`、`adversarial_suffix`、`fake_system`、`leakage`、`logic_trap` 均为 1.0。

结论：真实大模型 API 环境中，无防御网页摘要 Agent 存在可复现的外部检索源间接提示注入风险。

### 5.2 在线端到端防御对比

`outputs/tables/end_to_end_metrics_api.csv` 显示，在线 P7.4 中：

1. `no_defense`：ASR 0.894737，DSR 0.105263，Clean Success Rate 1.0，FAR 0.0。
2. `ours`：ASR 0.0，DSR 1.0，Clean Success Rate 1.0，FAR 0.0，Precision/Recall/F1 均为 1.0。
3. `ours` 平均延迟为 4234.178 ms，P95 为 10032.610 ms，平均审计调用为 0.6。

需要特别说明：该表 `stage_gate=False`，原因是原离线门槛要求 `ours` 平均延迟低于 `llm_auditor`。在线环境下 `ours` 平均延迟 4234.178 ms，略高于 `llm_auditor` 的 4152.816 ms，因此未满足延迟优势门槛。安全性、可用性和误报指标本身是通过的。

### 5.3 在线双环验证

`outputs/tables/dual_loop_metrics_api.csv` 显示，在线 P7.3 API MoE Dual-loop 在 17 条 dual-loop/clean 样本上 Precision/Recall/F1 均为 1.0，FAR 0.0，Logic Trap Recall 1.0，Leakage Block Rate 1.0，Intent Alignment Accuracy 1.0。反射审计 API 平均延迟为 5090.884 ms，P95 为 5946.778 ms，JSON 解析失败率为 0.0。

结论：真实大模型结构化反射审计已经补齐，且在当前测试集上补足了 Perception Only 对逻辑陷阱和数据泄露样本的盲区。

### 5.4 在线消融实验

`outputs/tables/ablation_metrics_api.csv` 显示，在线 P7.5 full system 在 69 个 case 上 ASR 0.0，DSR 1.0，Clean Success Rate 1.0，FAR 0.0，Precision/Recall/F1 均为 1.0。候选回答来自真实 API，并通过缓存跨消融变体复用，文档记录真实 API 调用 69 次、缓存命中 345 次、总体缓存命中率 0.833333。

消融结论与离线一致：

1. 去除滑动窗口后 Long-tail Recall 从 1.0 降至 0.0。
2. 去除规则/PPL 特征后 Perception Attack Recall 从 1.0 降至 0.306452。
3. 去除反射式意图后 Reflection Contamination Recall 从 1.0 降至 0.0。
4. 去除逻辑/泄露专家后 Logic Trap Recall 和 Leakage Block Rate 均从 1.0 降至 0.0。
5. 去除动态仲裁后 FAR 从 0.0 升至 0.142857。

### 5.5 在线动态仲裁真实延迟

`outputs/tables/arbitration_latency_api.csv` 显示，在线 P7.6 共 48 条仲裁记录，其中动态仲裁触发 12 次真实流式 API 深审计，API 错误数和回退数均为 0，TTFT 可观测率为 1.0，总 token 数为 1869。

动态仲裁总体真实延迟为：平均 TTFT 264.061 ms，P95 TTFT 623.731 ms，P99 TTFT 968.486 ms；平均 E2E 328.816 ms，P95 E2E 721.478 ms，P99 E2E 1059.863 ms。low 风险下动态仲裁平均审计次数为 0，high 和 critical 风险平均审计深度均为 4，critical Block Rate 为 1.0。

结论：真实延迟实验支持“低风险减少审计，高风险加深审计”的动态仲裁机制，但整体延迟不应被表述为绝对最低，而应表述为风险自适应的安全性和可用性平衡。

### 7.2 在线总验收表已生成但需解释状态

在线补充方案要求生成 `outputs/tables/p7_api_acceptance.csv`，用于汇总在线表格、日志和图表的通过情况。当前已生成该文件，并列出在线表格、日志、API 输出缓存和关键端到端指标。由于 P7.4 在线端到端结果沿用严格延迟门槛，`p7_api_acceptance` 总验收行当前为 `stage_pass=False`，报告时应解释为“在线安全指标成立，但严格延迟优势未通过”。

### 7.3 在线 P7.4 延迟门槛需要调整或解释

在线端到端防御中，`ours` 的安全效果非常明确，但 `stage_gate=False`。最终论文和答辩中需要避免简单写“在线 P7.4 全部通过”，更准确的表述是：在线安全性、可用性和误报控制成立；延迟优势相对 `llm_auditor` 在当前实现和样本分布下未形成，需要结合 P7.6 真实延迟实验解释动态仲裁的价值。

### 7.4 P3 训练版轻量分类器仍是可选增强

`docs/模型训练与实验准备说明.md` 明确指出，当前 DistilBERT 路径只进入 feature fallback，尚未真正加载微调后的 `AutoModelForSequenceClassification`。如果论文需要强化“轻量化类 BERT 分类器”的表述，建议补充窗口级二分类训练脚本、checkpoint 加载逻辑和 trained 版本 P7.2 对比。

### 7.5 统计置信表达仍需补充

在线补充方案要求正式报告尽量包含平均值、标准差、最小值、最大值和 95% 置信区间。当前 CSV 已覆盖均值、P95、P99 等关键指标，但最终论文中仍建议补充波动性和置信区间，尤其是在线 P7.1 的 mixed 类型攻击波动。

## 9. 可直接写入论文的阶段判断

当前系统已经达到“可展示、可复现实验闭环”的状态。离线结果证明 DSS Guard 的模块功能、指标链路和 P7 验收成立；在线 API 结果进一步证明真实大模型环境下存在可复现间接提示注入威胁，并且 DSS Guard 可以把无防御在线 ASR 从 0.894737 降至 0.0，同时保持 Clean Success Rate 1.0 和 FAR 0.0。
